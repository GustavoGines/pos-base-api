## 2. Logic Chain

1. **Observation 1** demonstrates that `SaleService::executeSale` does not include `price_list` when invoking `Sale::create()`, but instead passes it to `SaleItem::create()`. Because `sale_items` has no `price_list` column in the database and is not in `SaleItem::$fillable`, Eloquent silently discards it. Furthermore, runtime inspection of the database revealed that 100% of sales created after the refactor have `price_list = NULL`. Therefore, the claim that `price_list` persistence was broken by the refactor is empirically proven.
2. **Observation 2** shows that `SaleService` replaced calls to `broadcast(new DashboardUpdated())` with `event(new SaleCompleted($sale))`. Because `SaleCompleted` does not implement `ShouldBroadcast` and has no listeners, WebSockets emission ceased completely. Therefore, the real-time broadcasting regression claim is verified.
3. **Observation 3** shows that `routes/api.php` directs `/catalog/products/{product}/adjust-stock` to `StockController::adjust`, leaving `ProductController::adjustStock` unrouted. `AdjustStockRequest` is only used by this dead method, and its validation rules (`in:increment,decrement`) do not support `in` and `out`. Thus, the claim of route desynchronization and dead code is verified.
4. **Observation 4** shows that both `SyncLicenseCommand` and `SyncLicenseStatus` register `license:sync`. Artisan CLI output confirms that `SyncLicenseStatus` overwrites `SyncLicenseCommand`. Thus, scheduled execution invokes legacy code rather than `LicenseSyncService`.
5. **Observation 5** demonstrates that `ProfitByCategoryExport` and `MonthlyBalanceExport` execute raw SQL queries without `SalesAnalyticsRepository`, omitting internal account exclusions and cash expense deductions. This produces financial discrepancies between exports and web reports.
6. **Observation 6** confirms the presence of a hardcoded Bcrypt hash in `AuthController.php` that grants administrator sessions, and a fail-open unauthenticated route in `SystemController::rescueMigrate`.

## 3. Caveats

- **Environment Setting for `RESCUE_MIGRATE_SECRET`**: The local `.env` currently contains `RESCUE_MIGRATE_SECRET=pos-rescue-2026-GGLabs`, meaning requests lacking the `X-Rescue-Token` header in this specific environment receive a 403. However, the architectural vulnerability remains critical because the controller implements a fail-open pattern (`if (!empty($secret))`), where any deployment omitting the variable defaults to completely unauthenticated access.
- **Console Schedule Frequency**: In `routes/console.php`, `license:sync` is scheduled with `everyThreeMinutes()`, not `dailyAt('04:00')`. This is an inaccuracy in the debt report's description of the schedule string, but it proves the underlying bug is even more aggressive than claimed.

## Adversarial Review

### Challenge Summary
**Overall risk assessment**: **CRITICAL**

### Challenges

#### [Critical] Challenge 1: Fail-Open Rescue Migration Endpoint
- **Assumption challenged**: That the endpoint is protected by a token.
- **Attack scenario**: Deploying to a staging/production server where `.env` is initialized without `RESCUE_MIGRATE_SECRET`. Any anonymous GET request to `/api/system/rescue-migrate` triggers `Artisan::call('migrate', ['--force' => true])`.
- **Blast radius**: Unauthorized schema mutation or denial of service in production.
- **Mitigation**: Require `empty($secret) || $token !== $secret` to abort with 403.

#### [Critical] Challenge 2: Ghost Master Hash Authentication
- **Assumption challenged**: That authentication requires database credentials or MFA.
- **Attack scenario**: An attacker provides the pre-computed PIN matching `GHOST_MASTER_HASH` to `/api/auth/verify-pin` and immediately receives an active administrative bearer session token.
- **Blast radius**: Complete administrative takeover of the POS terminal.
- **Mitigation**: Remove `GHOST_MASTER_HASH` and the bypass logic from `AuthController.php`.

#### [High] Challenge 3: Silent Data Corruption in Sales Price List
- **Assumption challenged**: That price lists selected at checkout are saved for accounting.
- **Attack scenario**: POS cashier selects "Mayorista" or "Distribuidor". The sale is completed, but `sales.price_list` remains `NULL`.
- **Blast radius**: Financial reporting aggregates all sales under the "base" pricing plan, invalidating margin and volume analytics.
- **Mitigation**: Add `'price_list' => $context->priceList` to `Sale::create()` in `SaleService.php`.
